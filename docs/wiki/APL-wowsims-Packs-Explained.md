The **wowsims.com priorities** are the built-in priorities of Hekili Forever. Each one is generated by a translator from the rotation that the [wowsims.com](https://wowsims.com) simulator uses for that specialization, and none is written by hand. This page explains how they are made, why their lines are long, and what happens to a copy of one when the addon updates.

## Generated, never hand-edited

wowsims.com, from the [wowsims/forever](https://github.com/wowsims/forever) project, simulates WoW Forever combat and ships a default rotation for each specialization. Hekili Forever takes that rotation as data and translates it, entry by entry, into a priority with the addon's own ability and aura keys:

1. A recipe for each specialization, in `tools/wowsims/specs/`, names the wowsims build to use and maps wowsims's spell IDs to the addon's keys.
2. The translator, `tools/wowsims/apl.lua`, turns the rotation into SimulationCraft-style text, one line per rotation entry, in the same order.
3. `make packs` builds that text into the class addon.

Each rotation is taken from one recorded version of wowsims/forever. To change a built-in priority, a developer changes the recipe or the translator and generates it again; the generated file itself is never edited ([Pack wowsims recipes](Pack-wowsims-Recipes)).

The top of every generated priority says where it came from. From Feral (wowsims.com), shortened:

```simc
# Feral (wowsims.com): the wowsims/forever default APL for Feral (ui/specs/druid/feralcat/apls/adaptive.apl.json), translated to this addon's keys.
# Generated by `make wowsims-packs` (tools/wowsims/apl.lua) from tools/wowsims/specs/druid_feral.lua: edit that recipe, not this file.
# Omitted: default #5: waitUntil
# Omitted: default #15: selectedConjured
```

The `# Omitted:` lines list the rotation entries the translator left out, by list and entry number, with the reason: an action the addon cannot recommend, such as swapping items or picking a conjured item, or a wait.

## What (wowsims.com) in a name means

A priority whose name ends in "(wowsims.com)" is the translation of that specialization's wowsims.com rotation. There is one for each supported specialization, and it is the default. A specialization for which wowsims.com has no rotation has no built-in priority.

The translation follows wowsims.com as closely as the Forever client allows. Where the client forces a difference, the translator records it. The main ones:

- **Time to die.** wowsims.com knows when the fight ends. On Forever, `fight_remains` reads 3600 seconds, so lines that act near the end of the fight do not fire.
- **Distance.** wowsims.com knows the distance in yards. Hekili Forever brackets it with range checks, so a distance test becomes `target.within<N>` or `target.outside<N>`.
- **Movement.** wowsims.com walks the character. Hekili Forever cannot move the player, so movement terms are dropped, and the **Movement** toggle decides whether an ability out of range is shown ([Why a built-in looks verbose](#why-a-built-in-looks-verbose)).

The [Accuracy](Accuracy) page measures, for each specialization, how often the built-in priority recommends what wowsims.com would cast.

Some groups of a wowsims.com rotation can be switched on and off in the simulator. They become settings of the specialization, read in the priority as `settings.wowsims_<name>` and shown in the specialization's options ([Specialization options](Specializations-Reference)). From Arms (wowsims.com):

```simc
actions+=/whirlwind,if=settings.wowsims_stance_dance
```

## Why a built-in looks verbose

A built-in line is longer than a hand-written one would be, for four reasons.

- **Leveling guards.** wowsims.com simulates a character at full level with every ability. A character still leveling may not have an ability a condition reads, so each such read is wrapped in a test of whether it is known: `(!action.cat_form.known|buff.cat_form.up)` means "in Cat Form, or Cat Form is not learned yet". Without the guard, a line would wait for an ability the character cannot have.
- **The movement term.** A line that wowsims.com would walk to reach carries `(toggle.movement&target.outside5|target.within5)`: it is shown when the target is in range, or, with the **Movement** toggle on, while the player still has to close the distance.
- **Inlined values.** wowsims.com's named values are written out in each line that uses them, rather than as `variable` lines.
- **Groups as lists.** Each group of the rotation becomes a sub-list called with `call_action_list`.

From Feral (wowsims.com):

```simc
actions+=/cat_form,if=!buff.cat_form.up&(toggle.movement&target.outside5|target.within5)
```

A few additions come from the recipe rather than from wowsims.com, each with its reason written in the recipe: lines for a character below the level wowsims.com simulates, talent requirements for lines written for one talent build, focus tiers for the Timeline display style, and extra lines for content wowsims.com does not model.

## A copy freezes

A copy of a built-in priority keeps the lines it had when it was copied. When a new version of the addon regenerates the built-in priority, from a newer wowsims.com rotation or a corrected translation, the built-in one updates and the copy does not. The copy keeps working, but it no longer matches the built-in one or the [Accuracy](Accuracy) measurements.

To keep up with updates:

- Use the built-in priority where possible. The per-ability options and toggles change what it recommends without a copy ([Abilities and items](Abilities-And-Items), [Toggles](Toggles)).
- If you keep a copy, compare it with the built-in priority after each update, and copy again when the built-in one has changed.
