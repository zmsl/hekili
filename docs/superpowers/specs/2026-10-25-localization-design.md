# Localization on AceLocale-3.0: design

Date 2026-10-25. Branch `forever-localization` (draft PR zmsl/hekili#12). Status: proposed.

Starting point: the contributor's seven commits (`c3b81f5c3..f130881b4`) add a homemade `ns.L` (an `__index`
identity table, `Locales/Locales.lua`), `Locales/zhCN.lua` (1010 translated lines, core and pack strings in one
file), `tools/locales.py` with `tests/tools/test_locales.py`, `Hekili.L` on the content surface, a `GetLocale`
facade row, and ~1100 `L[...]` wraps (768 in `Options.lua`, 156 `StyleOptions.lua`, 72 `ChatCommands.lua`, the
rest in UI, Engine and the class packs).

Owner rulings (binding): AceLocale-3.0; we own the refactor; zhCN becomes a pure data file against our string
table; reuse `tools/locales.py` if sound; **enUS output byte-identical before and after**.

Verdict on the contributor's work: the wrapping is kept as is (keys are the English literals, so it is
byte-identical by construction except where a string was restructured, see §8). `tools/locales.py` is sound (a real
Lua 5.1 literal scanner, format/colour/texture/newline code checks, unit tests) and is kept and extended. What
changes: the runtime table (AceLocale), where pack strings live, the content surface, and the checks.

## 1. AceLocale silent mode; the enUS table

**Decision.** Vendor `AceLocale-3.0` into `src/Hekili/Libs/` (same Ace3 release as the other Ace libs; one line in
`embeds.xml`, a row in `Libs/CREDITS.md`). It is not embedded today: only AceConfig/AceGUI/AceDB etc. are. Every
addon gets `Locales/enUS.lua`, generated by `tools/locales.py`, first in its locale block:

```lua
local L = LibStub("AceLocale-3.0"):NewLocale("Hekili", "enUS", true, true) -- isDefault, silent
L["Forecast window (s)"] = true
```

Each other language file: `local L = LibStub("AceLocale-3.0"):NewLocale("Hekili", "zhCN") if not L then return end`.
Core: `Locales/Locales.lua` loads last in the block and does `ns.L = LibStub("AceLocale-3.0"):GetLocale("Hekili")`.
`ns.Locale` and the `GetLocale` facade row go (`tools/api_inventory.txt` back to 120 rows, `facade_spec` count back).

**Why.** Silent (`true`, not `"raw"`): a missing key answers the key, which is the contributor's semantics and what
keeps enUS identical; non-silent mode fires `geterrorhandler()` per missing key in game, and we catch missing keys
statically instead (§7). `silent` only counts on the app's first `NewLocale`, which is why enUS is first and the
generator, not people, writes that line. The enUS file is the string table zhCN is a data file against: `--check`
fails when it differs from the keys the code uses. `L[k] = true` stores the key as its value, so enUS output is the
literal. AceLocale reads the client's `GetLocale` itself (Libs are outside the facade checks; `fake_api` already
answers `"enUS"` headless) and maps enGB to enUS.

**Cost.** One vendored lib (~140 lines); one generated file per addon (~1000 short lines in core, under 20 per pack);
`Locales/Locales.lua` shrinks to two lines.

## 2. Per-pack locale files

**Decision.** Each addon owns its strings under its own AceLocale app named after the addon folder: core `"Hekili"`,
packs `"Hekili_Druid"` etc. A pack ships `src/Hekili_<Class>/Locales/enUS.lua` (generated) plus one file per language
it has, listed in its TOC before the class file. `tools/locales.py` moves the nine pack sections now at the end of
core `zhCN.lua` (lines 1014-1074) into `src/Hekili_<Class>/Locales/zhCN.lua`, verbatim. Core holds no pack string.
`Hekili_Shared` has no strings today; it gets locale files only when it does.

**Why.** Core-is-generic: core `zhCN.lua` currently holds "Curse of the Elements", "Demoralizing Shout", spec names.
That is class content in `src/Hekili`. Separate apps also stop collisions. The core's `L["Combat"]` (in combat) and
Rogue's spec `L["Combat"]` are one key today, so a translation for one is forced on the other. A pack that is not
installed costs nothing; a new pack needs no core edit.

**Cost.** Nine new `Locales/` dirs (enUS + zhCN each), nine TOC edits. `locales.py` loops over addons rather than
one `LOCALES` path; `toc_files` stops skipping `Locales/` for the TOC-order test only. The boundary scan skips
`src/Hekili_*/Locales/` as data, as it already skips pack share strings (they call `LibStub`, which content code may
not).

## 3. Content API 9 → 10

**Decision.** `Hekili.L` is removed. Content code gets its table with `local L = Hekili:GetLocale("Hekili_Druid")`, a
one-line core method (`return AceLocale:GetLocale(app)`) documented on the content surface. Bump `CONTENT_API` to 10
in `Engine/Content.lua` (with a history line: "10 (2026-10-2x): Hekili:GetLocale(addon); packs ship Locales/") and
`## X-Hekili-ContentAPI: 10` in all ten content TOCs (`Hekili_Shared` + nine class packs).

**Why.** Compared with `origin/forever` the surface gains a method packs call at load. A v10 pack on a v9 core would
raise on a nil method, and the version check turns that into the existing "update the older one" notice. A core
method keeps `LibStub` out of content code and the boundary allowlist (`PUBLIC` gains `GetLocale`, loses the
contributor's `L`).

**Cost.** Ten TOC lines, one Content.lua line, the boundary allowlist line. Test fakes that build `hekili = { L = ... }`
(`tests/Forever/helpers/engine.lua`, `load_druid.lua`, `load_warrior.lua`, `content_spec.lua`) get a `GetLocale`
returning one shared identity table instead.

## 4. Snapshots and debug print identifiers

**Decision.** Snapshot, `Hekili:Error`, `Hekili:Debug` and DevTools text prints `spec.key`, never `spec.name`. Change
the four places that print the name today:
- `Engine/Snapshot.lua:448` (`custom = format(" (*%s[%d])", state.spec.name, ...)`);
- `Engine/Schema/Spec.lua:2346` and `:2358` (`Hekili:Error(... spec.name ...)`);
- `Options/DevTools.lua:94` (`"Specialization: %s"`).

`status.specName` (`Engine/Sim/Core.lua:1545`, `Spec.lua:2418`) stays the name: displays show it to the player.

**Why.** A zhCN user's snapshot must still read and diff as English in a bug report. `spec.name` turns localized
the moment the packs wrap it.

**Cost.** Four one-word edits. The snapshot of a custom pack on enUS changes from `(*Arms[100011])` to
`(*arms[100011])`. That is debug text, not player output, so §8 exempts it and the owner accepts the change here.

## 5. Spell names from the client

**Decision.** Where the visible string *is* a spell or item name, read it from the client at registration/build
time (`Hekili.Client.C_Spell.GetSpellInfo(id).name`; core: `Facade.C_Spell.GetSpellInfo`), not a translated
literal. This applies to Warlock's `assigned_curse` values (Curse of the Elements / Recklessness / Weakness). Two
cases keep an `L[...]` string:
- sentences that mention a spell ("Keep Demoralizing Shout on the target…", "Maintain Thunder Clap"), because a
  translator places the client's term with the right grammar, which `format(L["Maintain %s"], name)` does not;
- spec (talent-tree) names. Forever reports one pseudo-spec per class, and the `wow` MCP lists no talent-tab name
  API on Forever, so there is no client source for "Arms"/"Feral". They are pack strings (§2).

Core pseudo-ability labels (`Potion`, `Trinket #1`, `Wait`, `Variable`…) are UI terms and stay `L`.

**Why.** The client's name is already translated in every language and matches the tooltip; the contributor's zhCN
can only drift from it. Read at build, the name is a plain string, never secret, with no per-frame cost.

**Cost.** Three Warlock values; the enUS client's DB2 names must equal today's literals (§8 pins it). Headless fakes
answer `"Spell <id>"`, so the §8 golden test gives the fake those three ids' DB2 names. A spell the client does not
return (no row on Forever, or not yet cached) falls back to the pack's `L[...]` string for it, so a nil name never
reaches the options tree: `info and info.name or L["Curse of Weakness"]` (owner, 2026-10-25). The client's official
zhCN name may word a curse differently from the description text the contributor matched to wowsimscn-forever; the
client's wording wins.

## 5b. Pack names: an identifier, shown through a label

**Decision** (owner, 2026-10-25). A pack's registered name stays its identifier everywhere it is stored or typed:
`class.packs[name]` (`RegisterPack`, `Spec.lua:1164`), the profile's `packs[k]` and `spec.package`, `RetirePacks`,
`/hekili priority <name>`, and import/export strings. Only display goes through one core helper, `PackLabel(name)`:
- a built-in pack (the name is in `class.packs`, registered by its pack) shows `L[name]` from that pack's own locale
  app (§2). Silent mode returns the English key when a language has no entry, so enUS is unchanged;
- any other pack (made or imported by the player) shows its name verbatim.

Packs keep calling `RegisterPack("Arms (wowsims.com)", …)`; their locale files carry the label like any other string,
and `tools/locales.py` extracts `RegisterPack`'s first argument. Every place a pack name is shown (at least the options
priority dropdown and the display's pack label; the plan lists them all) calls `PackLabel`. The slash command keeps
taking the key; also accepting the label is out of scope.

**Why.** Translating the name itself would orphan a player's saved pack and selection when they switch client
language, and imports between players on different languages would miss. A label keeps the storage stable.

**Cost.** One helper and its call sites; no Content API change beyond §3's. `tools/locales.py --check` flags a
translated label equal to another pack's key or label in the same spec (it would read as a duplicate).

## 6. docs/dev/architecture.md §3

**Decision.** §3 (content surface) lists `Hekili:GetLocale(addonName)` and the pack's `Locales/` files. §9 is
rewritten for AceLocale (apps per addon, silent, generated enUS, the never-localize list from §10, the lint from §7).
§5 (checks) names the locale check and the lint. `docs/dev/layout.md` names `Libs/AceLocale-3.0` and the pack
`Locales/` dirs; `DEVELOPMENT.md` keeps its one line ("run `python3 tools/locales.py`").

**Why.** §3 is the contract a pack author reads; a pack-facing method missing from it is undocumented API.

**Cost.** Doc edits only.

## 7. Lint: unwrapped player-visible strings

**Decision.** Part of `tools/locales.py --check`, not luacheck or busted. luacheck has no custom-rule hook, and the
Python tool already has the Lua literal/comment scanner the rule needs. It runs in `make check` through
`tools-test` (§9).

A **violation** is a string literal (or `..` chain of literals) containing an ASCII letter, not inside `L[...]`, in
one of these sinks:
1. a table field `name`, `desc`, `text`, `label`, `tooltipTitle`, `tooltipText` or `confirmText` whose value is the
   literal (AceConfig options, `UIDropDownMenu` entries, style labels);
2. a string value inside a `values = { ... }` constructor;
3. the first argument of `:SetText(`, `:SetFormattedText(`, `:AddLine(`, `:Notify(`, `:Print(`, and both of the
   first two of `:AddDoubleLine(`, including a literal format string (`format("...", …)` or `("..."):format(…)`)
   in that argument.

**Not violations:**
- a literal with no letter after stripping `|c........`, `|r`, `|T…|t`, `|A…|a` and format codes (`" "`, `": "`);
- `Hekili:Error`, `:Debug` and any other call not listed above;
- anything in `Libs/`, `Locales/`, `src/ForeverProbe/`, `Options/DevTools.lua`, `Engine/Snapshot.lua` and
  `Game/State/Snapshot.lua`;
- a line ending `-- l10n: verbatim`, for the product name ("Hekili Forever") and the like.

The rule is token-level, not a Lua parser. Known blind spot: a literal returned from a function assigned to `name`
(`name = function() return "Position" end`). Shortcut: those are rare (one in `Classic.lua`, already wrapped) and
review catches them; add a `return`-in-sink rule only if they recur.

**Why.** These sinks cover every place the contributor wrapped. A narrow, exact rule with a verbatim escape beats a
heuristic over every literal, which would flag option keys and APL text (§10).

**Cost.** ~60 lines in `locales.py`, plus `Sinks` cases in `tests/tools/test_locales.py`. The first run will list
leftovers: wrap each one, or mark it verbatim when it is on the §10 list.

## 8. Test: enUS byte-identical

**Decision.** `tests/Forever/enus_text_spec.lua` with golden `tests/Forever/fixtures/enus_text.txt`:
- Boot headless (`Game.harness.headless`, `fake_api` answers `enUS`) once per class world the harness has.
- Build the full AceConfig options tree, walk it and write every `name`, `desc` and `values` string (functions
  called with a stub `info`) as `path<TAB>field<TAB>text`, sorted.
- Add the output of each message the refactor restructured, called with fixed arguments:
  - `Content.lua` notices;
  - `Spec.lua` RestoreDefaults retired/updated/reverted, at 1, 2 and 3 names;
  - `State.lua` hold/unhold;
  - `Core.lua:93`, `:2095`, `:2147`;
  - `Events.lua:999` and `:1002`;
  - `Styles.lua`;
  - `UI.lua:1086`, the launcher text (`GetDataText`) for each mode;
  - `ChatCommands.lua` replies.
- Generate the golden **once at the merge base `1ef1a63b`**, before any wrap, from a throwaway checkout with the
  same dump helper, and commit it. After that the spec must match it byte for byte. `ENUS_GOLDEN=update` rewrites it
  for an intended English change.

**Why.** Wrapping a literal is identity by construction. The risk is the ~40 strings that were restructured:
concatenation turned into `format`, the `" and "` chain, `..`-split descriptions, `DISPLAY_NAMES`,
`customDefaults`, client spell names. A golden from the pre-change tree is the only proof of the ruling.

**Cost.** One spec (~120 lines), one fixture (~1500 lines), a one-off golden run at the merge base. The §4 snapshot
change is outside it (debug text).

## 9. `tools/locales.py --check` in `make check`

**Decision.** Already wired: `tests/tools/test_locales.py` runs `locales.main(["--check"])`, `make tools-test` runs
the tests, and `make check` runs `tools-test` (Makefile:128). Keep it. `--check` now also fails on the following,
and each failure prints the fix command:
- a stale `enUS.lua` in any addon;
- a §7 violation;
- a pack key found in core's language files.

**Why.** Nothing more is needed. A separate `locales-check` target would run the same thing twice.

**Cost.** None beyond §1, §2 and §7.

## 10. Never localized

These are keys, saved data, syntax or bug-report text. They stay English literals, and §7 leaves them alone or
marks them `-- l10n: verbatim`:
- option and setting keys (AceConfig `args` keys, `RegisterSetting` keys, `values` *keys*, select candidates read as
  `settings.<key>='<candidate>'`);
- spec, ability, aura, talent, pet, resource and toggle keys; `spec.key`; display ids (`Primary`, `AOE`, …: frame
  names and profile keys; shown through `DISPLAY_NAMES`); style registry names;
- priority pack names (`"Feral (wowsims.com)"`, `package = ...`; saved in the profile; built-in ones shown through `PackLabel`, §5b);
- SavedVariables names (`HekiliDB`), profile paths, saved custom-toggle names (only the defaults
  `Custom #1/#2` are translated, at display, as `customDefaults` does);
- `/hekili` command words and arguments (`set`, `toggle`, `cycle`, `on`, `off`, …) and slash command names;
- APL / priority text, the script language, import/export strings;
- `Hekili:Error`, `Hekili:Debug`, snapshot and DevTools output; `ForceUpdate` reasons, event names;
- font-flag and anchor-point *keys* (`MONOCHROME`, `TOPLEFT`); TOC metadata.

## 11. Secret values and performance

**Decision.** An `L[...]` key is always a literal (`--check` enforces it), so nothing secret can be a key, and a
lookup is one hash read. A silent miss does a one-time `rawset`. Messages pass only plain values to `format`:
names, counts, keys. Never pass a facade return that may be secret. Lookups go at load or build time. In
recurring code, hoist them to file-scope upvalues. The contributor's wraps on or near recurring paths:

| file:line | path | ruling |
|---|---|---|
| `Engine/Sim/Core.lua:2095` | inside `Hekili.Update`, the no-recommendation auto-snapshot branch (once per snapshot) | hoist the `L[...]` to a file-scope local |
| `Engine/Sim/Core.lua:2147` | end of `Hekili.Update`, only when snapshots were saved | hoist |
| `Engine/Sim/Events.lua:999`, `:1002` | `UNIT_SPELLCAST_SUCCEEDED` handler, behind once-only flags | fine (evaluated once) |
| `Engine/Sim/State.lua:6711`, `:6736` | hold/unhold from a command, `verbose` only | fine |
| `UI/UI.lua:845-853` | `GetDataText`, on toggle change and launcher tooltip | fine (event-driven) |
| `UI/UI.lua:1695-1742` | `ShowDiagnosticTooltip`, mouseover while paused | fine |
| `UI/UI.lua:281-284`, `:180-203` | config-mode mover tooltips | fine |
| `UI/UI.lua:1086` | `bindStyle`, display build, once per unknown style | fine |

No `L[...]` sits in a display `OnUpdate`, a style's render functions (`Classic`/`Timeline` wrap only `Options` and
`label`, built at load) or the driver. `format` there allocates as the old concatenation did, so allocation does
not change.

**Cost.** Two hoists in `Core.lua`.
