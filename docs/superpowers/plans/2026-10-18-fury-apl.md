# Fury APL Simplification and Pack Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Forever Warrior's Fury pack with the user's simplified priority (focus abilities, DoT/debuff upkeep by setting, Bloodthirst, Whirlwind, Heroic Strike/Cleave never clipping Bloodthirst or Whirlwind), after checking it against wowsims/forever's Fury implementation; and move every class's APL sources into its addon folder with a build step that re-encodes a changed pack and bumps its date so the game reports it updated.

**Architecture:** APL sources are SimC text per pack under `src/Hekili_<Class>/APLs/<Pack>.simc` with a manifest beside them; `tools/make_pack.lua` reads them, encodes the `RegisterPack` blocks into the class file only when the text changed, and sets the pack date to today's date on change; `make packs-check` fails on any drift. The Fury list follows the user's priority with wowsims used only to inform conditions and thresholds; every divergence from wowsims is reported, not silently applied.

**Tech Stack:** Lua 5.1, `tools/make_pack.lua` (parse/unparse/encode/decode/sync), busted, Go source reading (wowsims) for the comparison only.

**Spec:** the Design section below (user, 2026-10-18). Parent constraints: docs/superpowers/plans/2026-10-18-display-styles.md Global Constraints.

## Design

### Fury priority (user, 2026-10-18)
Focus abilities (`focus=1`): Victory Rush; Overpower when in Battle Stance; Revenge when in Defensive Stance;
Heroic Strike when `rage >= settings.hs_threshold` and `active_enemies = 1`; Cleave when
`rage >= settings.cleave_threshold` and `active_enemies > 1`. Then: keep Rend up; Sunder Armor when
`settings.maintain_sunder`; Thunder Clap when `settings.maintain_thunder_clap`; Demoralizing Shout when
`settings.maintain_demo_shout`; Bloodthirst; Whirlwind.

Clipping rule: Heroic Strike and Cleave (on-next-swing, `use_off_gcd=1`) are only recommended when,
after their cost, enough rage remains for Bloodthirst or Whirlwind if either comes off cooldown before
the next main-hand swing lands (the fork exposes `swing`/`rage.time_to_*`/`cooldown.*.remains`; use the
existing keys, add a small named variable in the list if it reads better). wowsims's rule for the same
thing is the reference for the exact condition.

Everything else in today's Fury list (adaptive queueing, execute phase queueing, slam/rend-without-BT,
hamstring filler, `ww_min_enemies`, `ww_cd_diff`, `hamstring_*`) is removed unless the Task 1
comparison shows the user's list is missing something essential, in which case it goes in the report
as a recommendation and is NOT added. Settings no longer referenced are removed from the Warrior file
(`RegisterSetting`), with their options.

### Pack sources in the addon folders
- `src/Hekili_Warrior/APLs/{Arms,Fury,Protection}.simc`, `src/Hekili_Druid/APLs/*.simc` (move with
  `git mv` from `tools/packs/<class>/`); the manifest moves beside them as
  `src/Hekili_<Class>/APLs/packs.lua` (`{ spec = ..., packs = { ... } }`, no date: the date is
  managed by the build) — or stays in `tools/packs/<class>.lua` if the tool's discovery needs it; the
  implementer picks the smaller change and records it. The TOC must NOT list the `.simc` files or
  `packs.lua` (dev-only; WoW ignores extra files in the folder).
- `tools/make_pack.lua write`: for each class, encode the packs; if the generated `RegisterPack` blocks
  differ from the class file ignoring the date field, set the class's date to today (`os.date("%Y%m%d")`)
  and write; otherwise leave the file untouched. The date persists in the generated block only (and in
  the manifest if the tool needs it as the "current" value: implementer's choice, but one source).
- `make packs-check` (already in `make check`) fails when a `.simc` changed without `make packs`.
- `tests/Forever/warrior_spec.lua` (and druid_spec) manifest/round-trip cases follow the new paths.
- `docs/dev/layout.md`: the APL source location and the date rule; `tools/packs/` README if any.

## Amendments (user, 2026-10-18)
These supersede the Design where they differ.
1. **Every wowsims Fury ability is modelled** (this supersedes "stay out" and Review Focus 5). Execute (after
   Bloodthirst and Whirlwind, `execute_phase`), Bloodrage, Battle Shout (refresh at <= 10 s), Death Wish, and the rest
   of what the clone's Fury APL casts: trinkets (`use_items`), Sweeping Strikes, Hamstring under Windfury, the
   Berserker Stance return, Berserker Rage with its talent, and the pre-pull Battle Shout and Intercept. They go in
   wowsims's order wherever the user's list does not fix it. Cooldowns go in a `cooldowns` list behind Arms's gate and
   the cooldowns toggle. None of them is focus. Racials, potions, engineering items and the Overpower stance dance are
   not modelled. The reasons are in `docs/research/2026-10-18-fury-vs-wowsims.md`, "Added from wowsims".
2. **Focus tiers.** `focus=N` is a priority tier, 1 highest (a plain `focus=1` still means tier 1).
   `tools/make_pack.lua` takes any positive integer and refuses 0, negatives and non-integers. Victory Rush,
   Overpower and Revenge are tier 1. Heroic Strike and Cleave are the lowest focus priority, two lines each:
   - tier 1 at `rage>=settings.rage_cap_threshold` (new setting, default 80), whatever the no-clip rule says
   - tier 2 at their threshold, with the no-clip rule

   **Timeline selection rule:** Record 1, if flagged (any tier), takes the Now circle (ready, gold, press
   affordances, unchanged). Otherwise, among flagged records i>=2 with exact_time - now <= focusHorizon, the lowest
   tier number wins; ties go to the soonest (lowest i). Task 3b implements this.
