## 3. Formulas and base tables

Formulas (vanilla/Classic 1.12 from memory, [UNVERIFIED on Forever]; the brief's "10 per point for the first 20, 20 per point after" does not match my recollection): max HP = classBaseHP(level) + 20-ish for the first 20 stamina at 1 HP each, then 10 HP per stamina point above 20, i.e. HP = base + stam_first(<=20)*1 + (stam-20)*10. Max mana = classBaseMP(level) + int_first(<=20)*1 + (int-20)*15. Percentage health mods (Tauren, Last Stand) apply after. Check on Forever: this client has Midnight-era secrets and buff numbers clearly retuned (PW:F rank 6 = +70 stamina in DB2 vs +43 in vanilla), so the per-stat ratios may have changed. ## 5. Where it could sit (options, not a design)

Existing declaration patterns:
- Resource `max` + `maxMods` (Families/Resources.lua:96-115, Families/Modifiers.lua:1-12): `max` = number or state-bound function (default 100); `maxMods = { { pct = n, when = fn|nil } }`; the product replaces the number until a plain read arrives (setMax, :134-150; R.maxRead :543-545, CombatEnd :599-601). Declared by the class (spec:RegisterResource(type, {max=..., maxMods=...}) via Adapter) or from races (Engine/Races.lua:66 RegisterResourceMod -> ns.raceMods.maxMods; Engine/Shared.lua:26-32). This already carries "+N% max" for mana; it cannot carry "+N stamina" (no stat concept) or "+flat".
- Aura definitions (Forever/Races/Tauren.lua:29, Gnome.lua:122, Forever/Shared/Auras.lua, Consumables.lua:22/27): `RegisterAura(key, { id, duration, max_stack })`; the player aura walk (Sources/Auras.lua) turns tracked ids into believed up/down (stack, remaining), plain out of combat. A new field on the aura (for example the stat or percent it grants) would be an additive declaration the core can read per aura index (like `costMods` resolves `aura` keys to indices in Families/Modifiers.lua:24-40).
- Stat cache (Sources/Player.lua + Families/Player.lua:104-127 I.STATS/statVal) already holds UnitStat(3) and (5) out of combat; mana/HP are derived from these plus a base. The `Stat()` accessor is VS.Stat (hybrid); the cache loses the info of WHICH stat buffs were active at read time.
- Nearest relatives for the derived value: Families/Player.lua (player health belief `health`, I.healthMax :33, VS.HealthMax :84-89, VS.Health :74-82; seeded in I.OnBuild :44-58; Obs.Read handler :61-66) and Families/TargetHealth.lua (a fraction belief with anchors and learned scale M "damage per full health", header lines 1-13; ordering of observed/modelled/pinned samples via I.Sample). - Placement constraints from CLAUDE.md-style rules in this fork (core/pack boundary): class/race facts (Fortitude ids, 5% racial) live in Forever/Classes, Forever/Races, Forever/Shared; core families read only declared fields. Packs get `all` shared auras via Engine/Shared.lua (Forever/Shared/Auras.lua).
